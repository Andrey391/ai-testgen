# Нагрузочный тест студии

Нагружает API студии так, как с ней работают люди: открыть студию и проект, список тестов с фильтрами и поиском,
тест с историей прогонов, задачи, дашборд, модель приложения, требования, наборы и покрытие; изредка — теги, комментарий
к тесту, статус задачи. «Ждёт вас» опрашивается раз в 30 с, как страница. Между действиями пользователь думает 1–3 с.
Без модели и без браузера: сессии Studio, прогоны тестов и конвейер в нагрузку не входят (их предел — число воркеров
и браузеров, а не API).

Данные — отдельная база `testgen_load` (синтетические проекты, тесты, прогоны, задачи), рабочие данные студии
не трогаются. Новых зависимостей нет: `httpx` уже в `requirements.txt`.

## Запуск (PowerShell)

```powershell
$py = "$env:LOCALAPPDATA\aitestgen\venv\Scripts\python"
# 1. Данные: 3 проекта × 1000 тестов × 20 прогонов, 150 задач на проект (база создаётся заново)
& $py -m loadtest.seed --projects 3 --tests 1000 --runs 20 --tasks 150
# 2. Студия на этой базе, на своём порту (другая база — своя блокировка, рабочая студия может работать рядом)
$env:TESTGEN_DATABASE_URL = "postgresql+psycopg://testgen:testgen@127.0.0.1:5432/testgen_load"
$env:TESTGEN_AUTH = "off"; $env:PORT = "8766"
& $py server.py
# 3. Нагрузка ступенями 25 → 50 → 100 → 200 пользователей, по 60 с замера на ступени
& $py -m loadtest.load --url http://127.0.0.1:8766 --stages 25,50,100,200 --hold 60 --out load-report.json
```

Ступень проходит, если p95 ≤ `--p95` (1000 мс) и ошибок ≤ `--errors` (1 %); код выхода 1, если не прошла хоть одна.
На каждой ступени печатаются RPS, p50/p95/p99 и самые медленные запросы; `--out` — то же в JSON.

С включённым входом — API-токен: `python -m testgen.auth token <имя> load`, затем `--token <токен>`.

Профили: `--think 1,3` (по умолчанию) — каждый пользователь непрерывно кликает, стресс; `--think 5,15` — обычная
работа человека. Несколько экземпляров студии на одной базе (командная установка, `docs/deploy.md`): у каждого свой
`PORT` и `TESTGEN_INSTANCE_URL`, `TESTGEN_EMBEDDED_WORKER=off`; адреса — через запятую в `--url`, пользователи
делятся между ними, как балансировщиком.

Один экземпляр — один процесс Python: его потолок — около 25 запросов в секунду на этих данных (3 ядра), то есть
около 100 одновременно работающих людей (`--think 5,15`). Больше — несколько экземпляров.
