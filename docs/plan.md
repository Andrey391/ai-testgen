# План улучшения AI Test Generator

30 сентября 2026 · живая версия с диаграммой дорожной карты — [https://claude.ai/code/artifact/5d3692eb-9fb9-465b-b9ee-57e8a45ba5b1](https://claude.ai/code/artifact/5d3692eb-9fb9-465b-b9ee-57e8a45ba5b1)

## Цель и исходная точка

Цель на 3–4 месяца — превратить студию в продукт, который можно поставить в российскую компанию и продать. Для этого он должен работать без Claude, проходить реальные корпоративные сайты и доказывать свою пользу цифрами.

**Позиционирование.** Не «генератор тестов»: это уже бесплатно делают Playwright Test Agents (Planner → Generator → Healer) и связка Claude Code + Playwright MCP. Продаём «ИИ-тесты, которым можно доверять». Это мутационная проверка проверок, самолечение только через ревью, классификация падений, установка на своём сервере и работа для ручного тестировщика без кода.

**Что уже есть.** План от 26 сентября выполнен (коммит 46add2f): регрессия в CI, история прогонов, карантин, мутации, Planner, доступность и визуальные проверки, API-тесты из трафика, MCP-сервер. Автотесты студии: 54 теста, 53 проходят, `test_password_never_reaches_claude_or_artifacts` нестабилен при прогоне всего набора.

**Главные пробелы:**

- LLM только через Anthropic API (`testgen/llm.py`) — в РФ это блокер: Claude официально недоступен, а служба безопасности не пустит скриншоты внутренних систем к зарубежной модели.
- Движок не проходит iframe, загрузку файлов, 2FA; каждый тест логинится через интерфейс; только Chromium.
- Интеграции — Jira, Confluence, Zephyr; в РФ переходят на Test IT, Allure TestOps, YouTrack, Яндекс Трекер.
- Нет цифр эффективности: доля рабочих тестов с первого раза, цена теста, экономия времени.
- Хранение в JSON-файлах, один процесс; нет SSO, ролей в проекте и журнала действий.
- Нет лицензии и модели распространения.

### 5.5. Хранилище и масштаб (8–10 дней)

Исходная проблема: данные были JSON-файлами под `threading.RLock` внутри одного процесса. Сейчас единственное хранилище — PostgreSQL (`docs/deploy.md`).

- [x] PostgreSQL (SQLAlchemy + Alembic) для проектов, тестов, задач, прогонов и пользователей; скриншоты, trace и HAR — в S3-совместимом хранилище (MinIO, Yandex Object Storage). Команда переноса из папок прежних версий — `python -m testgen.db import-files`.
- [x] Прогоны — в отдельных воркерах с браузерами по очереди задач; воркеры масштабируются горизонтально. Сессия Studio с Live View привязана к своему воркеру. Правило «один цикл для браузера» сохраняется внутри воркера.
- [x] Helm-чарт и `docker-compose` для рабочей установки, проверки здоровья, метрики Prometheus.

Как сделано: документы хранятся в PostgreSQL по тому же пути, что и в папках (таблица `docs`, JSON), бинарные файлы — в S3; все модули ходят к данным через `testgen/fs.py`, поэтому смена хранилища не затронула остальной код. Режима «одна машина, папки» и SQLite больше нет: без `TESTGEN_DATABASE_URL` студия не запускается, на диске только кэш браузера. HAR записанного трафика — JSON-документ в базе, не в S3. Набор раскладывается на задания по тестам, и они расходятся по воркерам. Сессия Studio живёт в экземпляре студии, который её начал (там браузер Live View); другие экземпляры передают ему запросы, привязка на балансировщике не нужна.

## Риски и критерии готовности

Главный риск — российские и локальные модели могут оказаться слишком слабыми для автора теста. Поэтому 1.1 (быстрая проверка через прокси) идёт первым: за 2–3 дня она покажет, стоит ли вкладываться в рынок РФ в текущем виде.

**Риски:**

- **Модели слабее Claude в агентной работе.** Противовес: текстовый режим, пошаговое подтверждение, модули шагов, разные модели по этапам. Если и этого не хватит — студия в РФ продаётся как «регрессия + анализ падений + рекордер», а ИИ-автор остаётся дополнительной функцией.
- **Генерация тестов становится бесплатной** (Playwright Test Agents, IDE-агенты). Противовес: продаём доверие и процесс, а не генерацию. Если 4.2 не покажет преимущества — стать модулем для Test IT или Allure TestOps.
- **Test IT и Allure сделают то же сами.** Противовес: скорость, открытое ядро, партнёрство вместо конкуренции.
- **Объём плана — около 100–130 рабочих дней** на одного разработчика, за 3–4 месяца в одиночку не успеть. Минимум для первых пилотов — этапы 0, 1, 2.1–2.4, 3.1, 4.1; этап 5 — под первого платящего клиента.
- **Новые места утечки секретов:** cookie сессии (2.3), TOTP (2.6), ответы API в `before` (2.4). На каждое — тест в `tests/test_agent_invariants.py` до слияния.
- **Ослабление запрета необратимых действий** в `after` (2.4). Противовес: только шаги, написанные человеком, и только данные этого прогона.
- **Расходы на бенчмарк** на четырёх моделях. Противовес: запуск вручную, бюджетные лимиты 4.3.

**Критерии готовности:**

| Этап | Готово, когда |
| --- | --- |
| 0 | 10 полных прогонов тестов студии подряд без падений; есть LICENSE; бенчмарк — 15+ сайтов со сценариями |
| 1 | Студия записывает и прогоняет тест на модели из РФ (GigaChat через прокси) и на локальной модели (vLLM) в контуре без интернета; есть таблица сравнения моделей. Сейчас не подтверждено замером: бенчмарка нет |
| 2 | Стенды iframe, shadow DOM, загрузки файлов и 2FA проходят агентом и в экспорте; набор из 20 тестов логинится один раз |
| 3 | Кейсы из Test IT и Allure TestOps становятся автотестами, результаты прогонов возвращаются туда же; интерфейс переключается на английский |
| 4 | Нужен бенчмарк (удалён): опубликован отчёт бенчмарка со сравнением с Playwright Test Agents и ручным написанием; лимиты расхода останавливают сессию |
| 5 | Два экземпляра студии и три воркера работают с одной PostgreSQL; вход через Keycloak; пользователь без доступа не видит чужой проект |
| 6 | 3 завершённых пилота с цифрами; хотя бы один переходит в платный договор |
