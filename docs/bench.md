# Бенчмарк моделей и подходов

Цифры, с которыми идём к заказчику и по которым выбираем модель: сколько тестов работает с первого
раза, ловят ли они дефекты, сколько стоят и насколько быстрее ручной работы.

## Набор сценариев

`bench/sites.json` — 15 сайтов и 50 сценариев: 9 страниц локального стенда `tests/site/` (вход, форма,
список, оплата в iframe, веб-компонент в shadow DOM, файлы, диалоги, вкладки, перетаскивание, 2FA,
код из письма, длинный каталог) и 6 публичных демо (Sauce Demo, The Internet, DemoQA, OrangeHRM,
Practice Software Testing, UI Test Automation Playground). У каждого сценария — ожидаемый результат и
внесённый дефект, у части сценариев стенда — вариант изменённой вёрстки `v2`.

Виды дефектов: `swallow_click` (клик по элементу с текстом ничего не делает), `hide_text` (текст
убран со страницы), `http_500` (запросы по маске отвечают 500), `script` (свой JS до загрузки страницы).

Публичные демо иногда меняются и падают: смотрите на колонку «Ошибка» в отчёте, прежде чем винить модель.

## Запуск

```bash
python -m testgen.bench                                  # модель по умолчанию, весь набор
python -m testgen.bench --provider gigachat --model GigaChat-2-Max
python -m testgen.bench --provider local --local-only    # только стенд: без интернета
python -m testgen.bench --site stand-login --limit 3     # часть набора
```

Каждый сценарий — настоящая генерация: это стоит денег. В CI бенчмарк запускается только вручную
(`.github/workflows/bench.yml`). Тесты бенчмарка сохраняются в проект студии «Бенчмарк» — их можно
открыть и разобрать.

Для каждого сценария: генерация в Auto-Pilot → три прогона на чистом сайте без самолечения → прогон с
внесённым дефектом → прогон на вёрстке `v2` с самолечением (стенд) → проверка мутациями.

Результат — `bench/results/<дата>-<провайдер>-<модель>.json` и `.html`. Доля рабочих тестов
сохраняется в настройках модели («Проект → Модели ИИ», колонка «Бенчмарк»): для моделей, кроме Claude,
Auto-Pilot включается, только если она не ниже порога проекта (по умолчанию 70%, «Процесс генерации →
Генерация теста»).

## Метрики

| Метрика | Как считаем | Ориентир |
|---|---|---|
| Рабочий тест с первой генерации | Доля сценариев, где тест прошёл 3 из 3 на чистом стенде без правок | ≥ 70% |
| Ловит внесённый дефект | Доля тестов, упавших на стенде с дефектом | ≥ 80% |
| Доля убитых мутантов | `mutations.py`, среднее по тестам | ≥ 70% |
| Переживает смену вёрстки | Прошёл на `v2` (запасные локаторы или самолечение) | ≥ 85% |
| Правки человека | Отклонённые и отредактированные шаги на тест (сессии Studio: `authoring_stats.edits`) | ≤ 2 |
| Время до готового теста | Медиана минут от сценария до сохранения | ≤ 10 мин |
| Стоимость теста | $ и ₽ за генерацию + самолечение (мутации без модели) | после замера |

## Сравнение моделей (этап 1.5)

Запустите набор на четырёх вариантах — Claude (эталон), GigaChat, модель Yandex AI Studio, локальная
VL-модель — и сведите результаты:

```bash
python -m testgen.bench compare bench/results/*-anthropic-*.json bench/results/*-gigachat-*.json \
    bench/results/*-yandex-*.json bench/results/*-local-*.json --html models.html
```

Решение по итогу: модель по умолчанию для установок в РФ и гибридная схема по этапам (например, автор
на локальной модели, анализ падений — на GigaChat).

## Сравнение с альтернативами (этап 4.2)

Те же 20 сценариев тремя способами: QA-инженер пишет вручную, Playwright Test Agents в Claude Code,
студия. Для ручного способа и Playwright Test Agents заполните `bench/external-template.json`
(время, стабильность — прогоны 3 из 3, дефект, доля убитых мутантов: мутации применяются к
экспортированному коду вручную или считаются по ревью) и сравните:

```bash
python -m testgen.bench compare bench/results/<студия>.json manual.json playwright-agents.json --html vs.html
```

Если студия не выигрывает у Playwright Test Agents хотя бы по качеству проверок и стабильности —
пересматриваем позиционирование (план, раздел «Риски»).
