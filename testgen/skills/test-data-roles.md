# Роли, возможности и тестовые данные в сценариях

## Роль сценария
- У каждого сценария есть роль (`role`) — точное название роли из модели приложения. Под учётной записью
  этой роли конвейер выполнит тест.
- Позитивный сценарий выполняет роль, у которой есть нужная возможность.
- Для каждого ограничения роли — негативный сценарий (тип «роли и права»): роль без права пытается
  выполнить действие и получает отказ (кнопки нет, доступ запрещён, ошибка 403), данные не меняются.
- Если одно действие доступно нескольким ролям с разными правилами (менеджер видит все заказы,
  покупатель — только свои) — отдельный сценарий на каждую роль с разным поведением.
- Новую роль, которой нет в модели, называй одинаково во всех сценариях: она попадёт в модель.

## Жизненный цикл
- Объект берётся в том статусе жизненного цикла, который нужен сценарию; статус достигается только
  разрешёнными переходами (для «отправленного» заказа нужен оплаченный).
- Ключевые разрешённые переходы — позитивные сценарии с ролью, которая их выполняет; запрещённые —
  негативные (отменить отправленный заказ нельзя).
- Предусловия называют сущности, их статусы и роль — сценарий не опирается на данные, которые не назвал.

## Тестовые данные сценария
- `test_data` — всё, что должно существовать до первого шага: сущность, имя, подробности, статус и
  роль-владелец. Пример: «Товар» «Тестовый товар А» — категория «Категория 1», цена 1000; в наличии;
  менеджер магазина.
- Если объект уже есть в тестовых данных модели — используй его точное имя: тесты переиспользуют один
  набор данных и не плодят дубликаты.
- Если объекта нет — дай ему описательное имя («покупатель с адресом доставки») и называй его одинаково
  во всех сценариях. Такие данные записываются в модель как «нужные»: первый тест, который их найдёт или
  подготовит, зафиксирует их, следующие — переиспользуют.
- Данные, которые тест создаёт сам на каждом прогоне (с уникальным именем), в `test_data` не входят —
  это шаги теста.
