# Публикация тест-кейса в Allure TestOps

## Создать или обновить
- Если у теста уже есть ID тест-кейса Allure — обнови этот кейс и перезапиши его сценарий. Дубликат не создавай.
- Если ID нет — поищи кейс с тем же названием в проекте; нашёлся — обнови, иначе создай новый.
- Если тест автоматизирует ручной кейс (в задаче указан его ID) — не создавай новый кейс, а обнови этот:
  добавь сценарий автотеста и отметь кейс как автоматизированный (automated = true), если инструмент это позволяет.

## Поля
- name — название теста; description — сценарий (что проверяется и ожидаемый результат).
- precondition — URL приложения и предусловия. Логин и пароль не указывай: «тестовые учётные данные проекта».
- tags — «ai-generated», тип сценария и теги теста.
- Приоритет (если поле есть в проекте): high → critical/high, medium → normal, low → low.

## Сценарий
- Каждый шаг теста — шаг сценария: название = описание шага; значение (текст ввода, URL) — в тексте шага.
  Плейсхолдеры {{username}}/{{password}} оставляй как есть: это не секреты.
- Для шагов-проверок добавь ожидаемый результат.

## Ограничения
- Ничего не удаляй и не архивируй. Не меняй чужие кейсы.
- Вызови done с ID кейса и ссылкой на него.
