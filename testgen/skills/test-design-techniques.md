# Техники тест-дизайна

Применяй выбранные для генерации техники, чтобы вывести сценарии из требований, а не придумывать их наугад.
В `covers` плана указывай, какое правило требований и какой техникой покрыто.

## Классы эквивалентности
Раздели каждое входное значение на классы, которые система обрабатывает одинаково, и возьми по одному
представителю: количество товара в корзине 1–99 → классы «<1», «1–99», «>99», «не число», «пусто».

## Анализ граничных значений
Для каждого диапазона — значения на границе и рядом: 0, 1, 99, 100; для длины строки — 0, 1, max, max+1.
Объединяй границы одного поля в один сценарий с таблицей данных, если поведение одно.

## Таблица решений
Правило с несколькими условиями — таблица «условия → действие»; сценарий на каждую значимую комбинацию.
Пример: скидка зависит от «есть карта лояльности» и «сумма ≥ 5000» → 4 комбинации, 3 разных результата → 3 сценария.

## Диаграмма состояний
Из жизненного цикла объекта (модель приложения): каждый разрешённый переход хотя бы раз и важные
запрещённые. Заказ: новый → оплачен → отправлен → доставлен, новый → отменён; проверь, что отправленный
заказ нельзя отменить и что заказ нельзя оформить с товаром, которого нет в наличии.

## Попарное тестирование
Много независимых параметров (браузер × роль × способ доставки × способ оплаты) — покрой все пары значений,
а не все комбинации. Перечисли наборы в инструкциях одного сценария или нескольких.

## Сценарии использования
Основной и альтернативные потоки каждой пользовательской истории от начала до конца, с ролью и
предусловиями.

## Предугадывание ошибок
Типичные дефекты: двойная отправка формы, кнопка «Назад» после отправки, устаревшие данные в другой
вкладке, одновременное редактирование, спецсимволы и очень длинные значения, часовые пояса и даты на
границе суток.

## Причина — следствие
Свяжи причины (входы, условия) со следствиями (результаты); сценарий на каждое следствие.

## Чек-лист
Пройди требования по пунктам: у каждого требования должен быть хотя бы один сценарий. Если требование
непроверяемо — запиши это в допущения.
