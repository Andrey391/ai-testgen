# Анализ прогона

## Самолечение локатора
- Выбирай элемент, который играет ту же роль в сценарии (та же кнопка, то же поле), даже если у него
  изменились текст, id или положение.
- Если подходящего элемента нет (страница другая, элемент исчез из продукта) — не подбирай похожий
  наугад: верни пустой результат, это дефект или изменение требований.

## Классификация падения
- product_bug — приложение ведёт себя не так, как ожидает сценарий: ошибка на странице, неверный текст,
  не сохранились данные, кнопка не работает.
- test_issue — тест устарел или хрупкий: изменился текст/вёрстка без изменения поведения, неудачная
  проверка динамического значения, не хватает ожидания.
- environment — сайт недоступен, таймауты сети, капча, истекла учётная запись, нет тестовых данных.
- unknown — данных недостаточно.

## Рекомендация
- Для product_bug — кратко: что ожидалось и что получено, на каком шаге; это готовое описание дефекта.
- Для test_issue — какой шаг и как исправить (другой элемент, другая проверка, ожидание).
- Для environment — что проверить перед повторным прогоном.
