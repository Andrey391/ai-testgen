# Модель приложения: жизненный цикл, роли, тестовые данные

Тесты генерируются только по подтверждённой модели приложения. Модель — общее описание тестовых данных
проекта: её читают проектирование сценариев, агент при записи теста и анализ падений, а найденные и
созданные тестами данные дописываются в неё и переиспользуются следующими тестами.

## Жизненный цикл системы
- Выдели сущности предметной области: что создаётся, меняется и удаляется в системе (Товар, Категория,
  Заказ, Покупатель, Заявка, Договор).
- Для каждой сущности — что должно существовать до её создания (`depends_on`): «Заказ» требует «Товар (в
  наличии)» и «Покупатель (с адресом доставки)»; «Товар» требует «Категория».
- Жизненный цикл — статусы и разрешённые переходы с ролью, которая выполняет переход:
  «новый → оплачен (покупатель) → отправлен (менеджер) → доставлен; новый → отменён (покупатель)».
  Отдельно — запрещённые переходы: «отправленный заказ нельзя отменить».
- Кто и как создаёт объект (`create`): «покупатель: корзина → оформление заказа».
- Правила, от которых зависит результат теста: лимиты, сроки, расчёты, уникальность.

## Роли и возможности
- Перечисли все роли пользователей. Если входа в систему нет — одна роль «Гость».
- Для каждой роли — возможности (`capabilities`): какие сущности видит, создаёт, меняет, в какие статусы
  переводит. «Покупатель: просматривает каталог, оформляет и оплачивает свои заказы, отменяет неоплаченный заказ».
- И ограничения (`restrictions`): что роли запрещено. «Покупатель: не видит чужие заказы, не меняет цены».
  Ограничения — источник негативных сценариев на права доступа.
- Роль связывается с учётной записью проекта («Проект → Тестовые данные → Роли»): под ней конвейер
  выполняет сценарии этой роли.

## Тестовые данные стенда
- Объекты, которые уже есть на стенде и на которые могут опираться тесты: сущность, имя, как его
  показывает приложение, важные подробности, состояние жизненного цикла, роль-владелец.
- Не выдумывай объекты: только то, что прямо сказано в требованиях или видно на страницах.

## Подтверждение
- Модель подтверждает человек («Проект → Тестовые данные → Подтвердить»): без подтверждённого жизненного
  цикла и ролей с возможностями тесты по требованиям не генерируются, конвейер ждёт.
- Изменение сущностей, жизненного цикла или возможностей ролей после подтверждения требует нового
  подтверждения. Данные стенда и память меняются свободно.
- Если в требованиях чего-то не хватает для модели (неясно, кто переводит статус, какие права у роли) —
  оставь поле пустым: человек допишет его при подтверждении.
