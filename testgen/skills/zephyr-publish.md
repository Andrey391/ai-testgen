# Публикация тест-кейса в Zephyr Scale

## Создать или обновить
- Если у теста уже есть ключ Zephyr (например PROJ-T12) — обнови этот тест-кейс и перезапиши его шаги.
  Не создавай дубликат.
- Если ключа нет — сначала поищи тест-кейс с таким же названием в проекте; если найден — обнови его,
  иначе создай новый.

## Поля тест-кейса
- name — название теста.
- objective — сценарий теста (что проверяется и ожидаемый результат).
- precondition — URL приложения и предусловия (например «пользователь авторизован»).
  Логин и пароль не указывай: только «используются тестовые учётные данные проекта».
- priority — High / Normal / Low, если приоритет известен (high → High, medium → Normal, low → Low).
- labels — «ai-generated» и тип сценария, если он известен.
- folder — папка из настроек публикации, если она задана (создай её, если её нет).

## Шаги (STEP_BY_STEP)
- Каждый шаг теста — отдельный шаг Zephyr:
  - description — описание шага;
  - testData — значение (текст ввода, URL, клавиша). Плейсхолдеры {{username}}/{{password}} оставляй
    как есть: это не секреты;
  - expectedResult — для шагов-проверок: что должно быть видно; для действий: краткий ожидаемый
    результат действия или пусто.
- Порядок шагов сохраняй.

## Ограничения
- Ничего не удаляй в Zephyr.
- Вызови done с ключом тест-кейса и ссылкой на него, если инструмент её вернул.
