# Запись UI-теста

## Шаги
- Один шаг — одно действие пользователя. Описание в повелительном наклонении, с названием элемента
  в кавычках: «Нажать кнопку 'Войти'», «Ввести 'kindle' в поле поиска».
- Выбирай элементы с понятным текстом или подписью: такие локаторы устойчивее при повторных прогонах.
- Не добавляй лишних кликов «на всякий случай» и не исследуй сайт: тест должен быть кратчайшим путём.

## Проверки
- После каждого значимого изменения состояния добавляй проверку: появился результат поиска, товар
  в корзине, сообщение об ошибке, сменился URL.
- Проверяй стабильный текст (заголовки, сообщения), а не динамический (время, случайные номера, цены
  со скидкой, если сценарий не про них).
- Для негативных сценариев проверяй конкретный текст ошибки, а не просто то, что что-то не произошло.
- Тест обязательно заканчивается проверкой ожидаемого результата сценария.

## Ожидания
- Не ставь ожидание «на всякий случай»: следующая проверка сама дождётся элемента.
- Явное ожидание нужно только для анимаций и отложенной загрузки, которые ломают следующий шаг.

## Данные
- Используй тестовые данные из сценария. Если их нет — придумай правдоподобные и безопасные
  (example.com для почты, тестовые номера).
